HEX ROUTER DESIGNER
===================

Запуск
------
1. Откройте index.html двойным щелчком в современном браузере или используйте GitHub Pages.
2. Приложение полностью автономно: сервер, установка и сетевые зависимости не требуются.

Интерфейс
---------
- На широком экране рабочее поле занимает основную часть окна, а параметры расположены в правой панели.
- При ширине окна 1080 px и меньше рабочее поле занимает всю доступную ширину. Параметры открываются кнопкой «Параметры» в выдвижной панели; на телефоне эта панель открывается снизу.
- В шапке находятся название проекта, текущий статус, выбор темы «Система / Светлая / Тёмная» и действия с файлами проекта.
- Параметры разделены на группы «Геометрия», «Трассировка», «Лента и питание», «Отображение», «Расчёт» и «Подключение».
- При назначении START/END и в режиме удаления над рабочим полем появляется явный индикатор текущего режима. Режим можно отменить крестиком или клавишей Esc.
- На сенсорных экранах область нажатия зелёных «+» увеличена без изменения их видимого размера.

Проект и габариты
-----------------
- Наименование проекта редактируется непосредственно в шапке. Оно сохраняется в JSON и выводится в PDF.
- Переключатель «Ориентация» разворачивает всю конструкцию на 90 градусов.
- «Требуемая ширина, мм» и «Требуемая высота, мм» находятся в группе «Геометрия» и задают ориентир. Когда заполнены оба значения, на схеме появляется тонкая красная рамка требуемых габаритов, центрированная относительно фактической серой рамки.
- Базовая и итоговая длина ребра отображаются как вычисляемые значения, а не как редактируемые поля.
- Серая рамка показывает фактические габариты конструкции. Обе рамки и их размеры попадают в PDF.
- «Вписать» масштабирует все видимые элементы с полем не менее 20 px. При добавлении нового шестигранника приложение автоматически выполняет такую подгонку только если схема перестала полностью помещаться в рабочем поле.

Создание конструкции
--------------------
- Первый шестигранник можно поставить в любом месте рабочего поля.
- Следующие шестигранники добавляются зелёным «+» на свободном ребре существующей конструкции.
- Конструкция всегда остаётся одной связной группой.
- Для удаления нажмите «Удалить», затем нужный шестигранник. Удаление, разрывающее связность, отклоняется.
- Доступны Undo/Redo, панорамирование, масштабирование и анимация маршрута.

Рёбра и нумерация
-----------------
- «Ребро» — уникальный физический участок между двумя вершинами. Совпадающие стороны соседних шестигранников являются одним ребром.
- Номера рёбер присваиваются динамически при первом прохождении маршрута от START к END. Повторный проход по тому же ребру сохраняет его первый номер.
- Номера шестигранников также динамические: в первую очередь учитывается минимальное расстояние по рёбрам от START, затем первое появление шестигранника вдоль маршрута, затем визуальное положение.
- Параметры отображения собраны в отдельной группе «Отображение». Можно независимо показывать № шестигранников, № рёбер и № шагов маршрута, а также диагностику нечётных узлов.

START / END
-----------
- AUTO выбирает две разные допустимые точки на нижнем внешнем контуре.
- START и END можно назначать вручную.
- Критерий оптимизации выбирается прямым двухпозиционным переключателем: «Минимум повторов» или «Избегать общих рёбер».
- В ручном режиме START и END разрешено назначить на одну и ту же вершину. В этом случае строится замкнутый маршрут, который начинается и заканчивается в этой точке; на схеме отображается «START / END».
- Если после изменения геометрии или ориентации ручная точка перестаёт быть допустимой, приложение возвращается в AUTO с предупреждением.
- Для обычного маршрута DATA идёт от START к END. Электрические расчёты являются ориентировочными и не заменяют проверку падения напряжения, сечения проводов и защиты.

Лента и питание
---------------
Основные параметры:
- Сегментов на ребро;
- LED/м;
- Базовая длина ребра, мм — рассчитывается автоматически;
- Коррекция длины ребра, мм — может быть положительной, нулевой или отрицательной;
- Итоговая длина ребра, мм — рассчитывается автоматически;
- Вт/м, напряжение 5/12/24 В и запас БП.

Формулы:
baseEdgeMm = segmentsPerEdge × 1000 / LED_per_m
edgeMm = baseEdgeMm + edgeCorrectionMm

Итоговая длина ребра должна быть больше нуля. Именно edgeMm используется для геометрических габаритов, длины ленты, повторов, мощности, тока, оценки БП и физического расстояния START–END.

Файлы
-----
- Действия с файлами проекта находятся в шапке приложения.
- «Сохранить JSON» сохраняет канонический проект версии 3: название, ориентацию, требуемые габариты, геометрию, маршрутизацию, параметры ребра/ленты и настройки отображения.
- «Открыть JSON» читает проекты v3, а также старые v1/v2 с автоматической миграцией.
- «Экспорт для GyverTwink» скачивает отдельный файл gyvertwink-map.json с уже рассчитанным порядком и координатами всех светодиодов. Формат проекта v3 при этом не меняется.
- Пользовательского экспорта SVG больше нет.
- Кнопка «PDF» формирует PDF полностью локально в браузере и сразу скачивает файл. Отдельное окно PDF и системный интерфейс печати не открываются.
- PDF имеет минимум два листа A4 landscape. Лист 1 — схема. Лист 2 — параметры, расчёты и спецификация рёбер с дополнительными проходами. Если таблица длинная, она автоматически продолжается на следующих листах.

Экспорт для GyverTwink
----------------------
Designer полностью рассчитывает маршрут, порядок и положение светодиодов. Сторона GyverTwink получает готовую карту и не пересчитывает маршрут и не использует сведения о шестигранниках.

Файл: gyvertwink-map.json
Версия формата: gyvertwink_map = 1
Единицы: mm

Поля файла:
- gyvertwink_map — версия формата, сейчас 1;
- unit — всегда "mm";
- project.name — название проекта, пустая строка если название не задано;
- led_count — число светодиодов; равно leds.length и числу проходов маршрута × segmentsPerEdge;
- width_mm, height_mm — габариты экспортируемых точек и контура;
- start, end — координаты START и END;
- leds — все светодиоды строго в порядке ленты N1, N2, …; каждый элемент имеет вид [x, y];
- outline — каждое уникальное физическое ребро один раз в виде [x1, y1, x2, y2]. Это только подложка для отображения контура.

Система координат совпадает с Designer: X направлена вправо, Y вниз, текущая ориентация pointy/flat уже применена. Начало координат привязано к левому верхнему углу габаритов вершин. Координаты округляются до 0,1 мм.

На каждом проходе ребра при n = segmentsPerEdge светодиоды располагаются равномерно по направлению движения на долях k / (n + 1), k = 1…n. Для геометрии используется итоговая длина ребра edgeMm с учётом коррекции.

Повторный проход того же физического ребра создаёт собственные n светодиодов в соответствующем месте последовательности. При экспорте из интерфейса повторные проходы имеют небольшой боковой разнос 1,0 мм на номер повторного прохода, чтобы их точки не накладывались точно друг на друга. Разнос выполняется влево по ходу ленты и не меняет порядок светодиодов, количество светодиодов или физический контур outline.

Если трассируемой схемы нет, файл не создаётся и показывается сообщение «Сначала создайте трассируемую схему.».

Спецификация рёбер
------------------
В PDF отображаются только рёбра, по которым лента проходит более одного раза:
- № ребра;
- Дополнительные проходы.

Рёбра с единственным проходом в таблицу не включаются. Два прохода дают 1 дополнительный проход, три прохода — 2 и т. д.

Ограничения и безопасность
--------------------------
Электрические расчёты носят рекомендательный характер. Программа не моделирует падение напряжения, нагрев, сечение проводов, допустимый ток дорожек, конкретные предохранители или сертификационные требования. Перед изготовлением необходимо отдельно проверить эти параметры.
